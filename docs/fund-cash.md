# 基金可用现金

首页现金弹窗按账户展示全部持仓的基金现金（不受首页前七只持仓限制），支持手动修改、即时汇总并保存。首页现金与总资产继续使用账户汇总余额；不改变持仓成本和收益。

## 余额口径

- 同一用户、同一账户、同一基金代码共用余额。其他账户和用户完全隔离。
- 首次打开或首次确认新交易时，原账户现金完整保留为未分配现金，各基金初始分配为零。历史已完成交易不重复回放。增加基金分配自动扣减未分配现金，减少分配自动退回，总现金不变；未分配不足时拒绝该次调整并保留原值。直接修改未分配现金表示补充或取出资金，预览总额后保存。
- 总现金 = 未分配现金 + 各基金现金余额。记录已完成买入超出预算时保留负余额并提示待补资金，不吞掉差额，也不挪用其他基金的资金。手动保存需要核对并补齐负余额。
- 交易沿用现有系统确认完成时点记账：BUY / REGULAR_INVEST 扣交易金额 + 费用；SELL / 清仓记入交易金额 - 费用（不低于零）。进行中交易不提前记入现金，弹窗单独展示待确认买入金额及预计卖出金额；取消待确认流水不改变余额。
- 关联的基金转换将转入所需金额从转出基金现金转给转入基金后扣款，避免转出回款留在源基金、转入却出现无资金来源的重复占用。转出尚未完成时转入继续等待。未关联的转换分别按对应基金记录资金变化。
- 清仓后仍保留该基金余额；删除持仓后显示“已移除持仓，现金保留”，重新添加相同基金继续使用原余额。
- 这里的确认入账是现有交易流水的系统时点，不新增银行到账查询或自动下单能力。

## 一致性与迁移

部署前执行 `docs/sql/014_fund_cash.sql`（仅创建三张新表，幂等）。现金修改和交易确认使用账户行锁；交易事件唯一键防止同一流水重复入账。交易确认、持仓和现金更新处于同一个事务，每笔定时结算独立回滚，防止失败时留下半笔账。

弹窗携带版本号保存。编辑期间交易已完成，旧版本保存会拒绝，用户重新读取后修改。新增基金、重复基金、不完整基金列表和跨用户写入均被拒绝。启用基金账本后原总现金写入接口拒绝直接覆盖。

接口：`GET /api/portfolios/{id}/fund-cash` 读取全部余额及待确认交易；`PUT` 提交 version、unallocated 和完整 funds（fundCode、balance）。修改保留审计事件。

## 今日交易推荐：只读金额参考

- 继续使用已审核的 NAV-TA v3.1-trend / T70-B2-F20-S18-I3，不修改历史回测规则。Java 按登录用户、持仓所属账户和基金代码读取资金快照，合并同基金的已确认份额；Python 计算金额，前端仅展示和预览。分析不会初始化资金账本、修改余额或持仓，也不会新增、执行或取消任何交易流水。
- 当前持仓参考 = 已确认份额 × 最新正式单位净值；单基金策略资金 = 当前持仓参考 + 该基金现金。未分配现金、其他基金和其他账户资金不参与。未初始化或尚未分配时该基金现金按零读取。
- 目标仓位沿用进攻 100% / 防守 20%。偏离不超过 5 个百分点不调仓；新增买入还要求当前进攻趋势确认，不在防守阶段补建仓。每次建议买入不超过该基金现金的 50%，减仓不超过已确认份额的 50%，同时不越过目标；取整后不足 1 元不建议操作。
- 同基金或关联转换存在待确认交易、现金为负、份额与持仓矛盾时，展示明确原因且不给出金额。最近已完成买卖/定投/转换按交易日期与系统完成更新时间中较晚者计算，之后须新增至少 3 个净值观察点；周末、假期和反复查看不会消耗间隔。该时间口径偏保守，历史补录也可能需要等待。
- 非交易日仍可查看截至最新披露净值的分析，不把旧净值伪装成今日行情。买入金额是含费用的总支出预算；卖出金额、剩余现金和持仓为未扣实际费用的净值估算，实际份额、费用、成交日及到账时间由交易平台确定。该页面不额外模拟实际银行到账。
- 用户可修改本次预览金额，减仓可选择全部已确认份额清仓，加仓可预览更高金额。超过该基金现金时显示需要补充的差额，不自动挪用其他现金。全部清仓属于用户手动预览，不改变规则的 20% 防守目标。重新分析、切换基金或重新打开时恢复新建议。
- 金额调整不会改变原规则建议、不会保存成委托、不会扣减资金。用户自行在交易平台操作并登记流水后，仍由原交易确认流程更新现金和持仓。金额计算层版本为 FUND-CASH v1；它核对真实资金与待确认状态，不能将历史独立模拟账本的收益直接视为该账户的预期收益。
