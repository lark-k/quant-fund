## 项目背景

QuantFund 是一个 PC 优先的基金量化看板，目标参考“养基宝/养鸡宝”类产品的持仓监控、盘中估值、关联板块、收益日历、基金详情、净值走势、模拟交易、AI 量化建议等流程。技术栈：

- 后端：Spring Boot / MyBatis Plus / MySQL / Redis，包名 `com.lk.quantfund`
- 前端：Vue 3 / Vite / TypeScript / Pinia / Vue Router / Axios / Element Plus / ECharts
- 数据库：`quant_fund`
- 前端标题：`QuantFund - AI Fund Quant Dashboard`
- 视觉方向：PC 端深色交易终端风格

## 当前已修复但需要继续守住的规则

1. A 股盘中估值窗口必须是交易日 `09:30-11:30`、`13:00-15:00`；港股交易窗口是 `09:30-12:00`、`13:00-16:00`。
2. 非盘中估值窗口不能刷新或展示盘中当日收益。
3. QDII/海外基金不能因为 A 股盘中或延迟净值而更新“今天”的盘中当日收益。延迟正式净值可以同步到持仓净值，但收益必须归属到真实净值日期/结算日期，不能冒充今天收益。
4. 收益分析、收益日历、首页收益趋势依赖 `holding_snapshot`，如果昨天快照缺失，应自愈补写，避免 6/24 这类数据断档。
5. 基金详情的昨日收益必须来自昨日快照或昨日实际结算记录，不能固定返回 0。
6. 持有天数不能固定为 0，应按买入/创建日期和交易记录推导。
7. 持仓编辑更新时不能因中文/历史基金类型枚举导致 500，应返回可理解错误或自动归一化。
8. 盈利使用红色，亏损使用绿色。

## 业务逻辑缺口清单

### 1. 数据源与数据质量

- 检查 `EastMoneyFundDataSourceAdapter`，当前仍有大量 HTML/JS 解析和硬编码映射，且编码文案已有乱码风险。需要统一 UTF-8 文案，清理所有 mojibake。
- 基金搜索、基金详情、历史净值、重仓股、基金经理、同类排名、关联板块、市场指数、盘中估值都要通过真实数据源落库缓存。前端 `mock.ts` 只能作为显式开发模式使用，真实模式不得混用 mock 数据。
- 建立数据源健康状态：每个接口记录最近成功时间、失败原因、来源、是否延迟，前端系统配置页展示。
- 对东方财富接口做 provider abstraction：搜索、基础信息、历史净值、估值、重仓、主题、市场指数分别有独立 provider，可后续接入天天基金/新浪/腾讯/雪球/自建映射。

### 2. 交易日历与市场时段

- 当前 `TradingCalendarService` 只粗略处理周末和少量节假日。需要接入或维护 A 股、港股、美股交易日历，自动识别节假日和临时休市，例如用户反馈的 6/19 必须标记休市。
- 收益日历中非交易日必须显示“休/非交易日”，且不能参与胜率、盈利天数、亏损天数。
- A 股收盘后如果港股仍在交易，涉及港股/恒生/港股通基金要显示“港股交易中”；QDII/美股基金显示“海外市场参考/待海外收盘”，不能展示 A 股盘中当日收益。

### 3. 盘中估值与养基宝对齐

- 对齐养基宝逻辑：基金当日收益优先按关联板块/跟踪指数的盘中收益率估算，而不是简单使用基金估值接口。
- 指数基金/ETF 联接：必须识别跟踪指数，例如中证电网设备，不应归类为主动权益。
- 主动权益：根据真实重仓股、行业、主题映射做加权估算。权重不足时展示置信度和来源。
- QDII/海外基金：不要用 A 股时段刷新当日收益。要把海外市场、汇率、净值确认延迟独立处理。
- 每个估值结果必须带上：
  - `valuationDate`
  - `valuationTime`
  - `marketSession`
  - `source`
  - `basis`
  - `confidence`
  - `belongsToTradeDate`
  - `isFinalNav`

### 4. 正式净值结算与快照

- 定时任务不能只在 23:00 快照。正式净值一旦确认，应按净值日期写入或更新对应 `holding_snapshot`，并回填收益日历。
- 快照应按 `snapshot_date + holding_id` 幂等 upsert，不能重复插入。
- 当前 `HoldingSnapshotBackfillService` 只补昨天，是临时自愈。需要扩展为最近 N 个交易日补偿任务，启动时、访问收益页时、正式净值同步后都可触发。
- QDII 延迟净值必须写入其真实净值日期，而不是写入今天。
- 收益分析中的当天预估收益和正式净值收益要分层：盘中显示“预估”，正式净值同步后替换为“已确认”。

### 5. 持仓与交易流水

- 持仓编辑、买入、卖出、转换、定投都必须走统一成本法。卖出时：
  - 支持部分卖出和全部卖出；
  - 全部卖出后持仓可标记清仓/删除；
  - 成本按份额比例扣减；
  - 交易记录保留，收益日历可追溯。
- 持有天数应以首次买入日或用户录入的起始持有日为准，而不是系统创建时间。
- 持仓删除和清仓要区分：删除是不再展示，清仓是保留历史但当前份额为 0。
- 前端持仓编辑不应要求用户输入估算净值/正式净值，净值必须来自数据源。

### 6. 基金详情

- 基金详情必须全部真实数据驱动：
  - 基金基础信息、基金经理、基金公司、风险等级；
  - 历史净值走势；
  - 关联板块走势；
  - 业绩走势；
  - 重仓股；
  - 同类排名；
  - 我的收益；
  - 买入/卖出点位标注。
- 净值走势图要类似养基宝：本基金线、沪深300/相关指数线、成本线，红点买入、绿点卖出。
- 当前页面有 fallback holding，容易导致“未找到详情/空图”掩盖真实错误。应明确区分：无持仓但可查看基金详情、已持仓详情、数据源失败。

### 7. 收益分析与收益日历

- 收益日历必须从快照/交易流水/正式净值统一生成。某天不是交易日要标记休市。
- 当天盘中预估收益要展示为预估；正式净值确认后同步替换。
- 盈利 TOP5 只能包含盈利基金；亏损 TOP5 只能包含亏损基金。前端和后端都要过滤。
- 收益分析图表需要接入市场指数对比，不再显示“接入后启用”的占位。

### 8. AI 量化分析

- 真实 DeepSeek 调用必须可诊断：启动时读取 env/yml 后在系统配置页展示 `enabled/model/baseUrl/keyPresent/mockEnabled`，不要泄露 key。
- 如果 `DEEPSEEK_ENABLED=false` 或 `DEEPSEEK_MOCK_ENABLED=true`，前端必须明确指出是哪项配置导致 mock，而不是笼统说“未配置”。
- AI 输入上下文必须包含真实持仓、估值、正式净值、重仓、关联板块、近期收益、风险偏好、策略配置、快照趋势。
- AI 输出只允许模拟建议：观察、持有、分批买入、减仓、转换、止盈、止损。禁止自动真实下单。
- 首页 AI 今日建议和 AI 分析页必须使用同一份 `AiAnalysisReport` 数据。

### 9. 前端体验与 QA

- 所有菜单和页面文案必须中文且 UTF-8 正常显示，清理 mojibake。
- PC 端优先，首页卡片不能过小，核心指标优先，避免大面积空白和错位。
- 自选/持仓监控、持仓列表、基金详情的收益/收益率要留足间距，不可截断。
- 图表必须有非空数据、空状态、加载状态、错误状态。
- 使用 Playwright 做截图级 QA：桌面宽屏、普通 1440 宽、移动兼容至少各一张，检查文字不截断、图表非空、色彩规则正确。
