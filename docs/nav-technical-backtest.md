# NAV-TA 规则历史回测

入口：首页持仓基金 → 今日交易推荐 → 回测此规则。独立弹窗，不新增路由，不改动既有 QuantRuleEngine 或回测验证页面。

## 共用规则

当前今日推荐使用 Python `app/technical/trend.py` 的 NAV-TA v3.1-trend / T70-B2-F20-S18-I3（用户于 2026-10-01 审核启用），回测共享相同趋势及目标仓位逻辑。旧版 v1 / v2 保留于 `app/technical/rules.py` 供历史对照。以下原始 v1 说明仅描述旧版本：MA、MACD、RSI、完整周净值 K 线以及样本和新鲜度门槛与原前端规则一致。旧 TypeScript 实现仅保留为 `.reference.ts` 测试对照，不被应用组件导入。

逐日回放：当日 10:00 只读取按披露延迟假设已经可见的历史净值，再按当日尚未知的净值模拟成交。没有盘中 K 线、成交量或以当日收盘净值回填信号。

## 交易及数据假设

- 起点前需要 120 个已披露日净值；Java 加载起点前一年作预热。回测区间上限 5 年。数据不足返回可用起点提示；无效日收益率或大于 14 天的估值间隔拒绝模拟。
- 初始全现金，买入按可用现金比例（默认 25%），减仓按已确认份额比例（默认 50%）。连续相同信号仅首次执行；转为其他信号后再出现可重新触发。金额不足 1 元不成交。
- 申购费包含在买入资金中，净投入 = 申购金额 / (1 + 费率)。赎回先进先出，按日历持有天数分为不足 7 天、7–29 天、≥30 天三档，费用从赎回款扣除。
- 披露、确认、到账延迟以**净值观察日**计，默认分别为 1、1、3；QDII 披露至少 2。缺少历史真实披露时刻和逐基金开放日，不能称为真实成交复现。费率也只是可编辑的假设。
- 收益率构造再投资净值指数，模拟单位并非真实登记份额；不直接以未复权净值跳变计盈亏。现金及待到账赎回款不计利息。
- 期末不强制清仓；净资产包含现金、持仓、待到账款，扣除已发生费用，不扣假设期末赎回费用。基准用同资金、同起点及同申购费一次买入持有。
- 以系统 A 股配置日历过滤非交易日。当前 v1 新鲜度要求最多落后 1 个工作日，QDII 的 2 日披露假设可能使整个区间无可分析日；这时结果为 `NO_ELIGIBLE_DAYS`，明确提示不能验证，不放松门槛伪造建议。
- 不纳入申赎暂停、额度、真实历史披露修订、逐笔分红到账及实际产品费率。历史数据可能被源站修订。

## 展示与保存

收益/回撤曲线与买入持有对比，展示扣费后收益、最大回撤、相对收益、年化（不足一年不年化）、成交次数、费用及平均仓位。保留信号频次、每项条件未满足次数、数据阻断与无现金/份额等未成交原因，以及逐笔指标证据。

Java 独立表 `nav_technical_backtest` 保存参数、曲线、交易、逐日信号、规则/引擎版本、数据来源及输入数据 SHA256。列表显示最近 30 条；每个读取与运行接口均验证当前用户拥有该持仓，并以 user_id + holding_id 限制结果查询。不会修改实际持仓或交易。

## 接口

- `POST /api/holdings/{id}/nav-technical/analyze`
- `POST /api/holdings/{id}/nav-technical/backtests`
- `GET /api/holdings/{id}/nav-technical/backtests`
- `GET /api/holdings/{id}/nav-technical/backtests/{resultId}`
- 内部 Python：`POST /api/v1/nav-technical/analyze`、`/backtest`

回测为同步请求，界面显示运行状态。关闭弹窗会取消客户端等待，服务端已开始的计算可能继续完成并保存，可从历史结果重新查看。重复提交有频率限制。

## 部署和验证

先执行增量 SQL `docs/sql/013_nav_technical_backtest.sql`（仅新表，幂等），再重建 Python / Java / web 三个容器。本地迁移工具 `tools/NavBacktestMigration.java --apply` 使用既有环境配置，不输出凭据。

- Python：迁移数值对照、信号类型、复权、无未来泄漏、现金守恒、分档费用、到账锁定、重复信号、数据不足与 QDII 无可分析日。
- Java：持仓权限、结果持久化、用户/持仓隔离、同引擎调用；原 QuantBacktestService 回归。
- 浏览器：`quant-fund-web/scripts/nav-backtest-check.js` 使用独立 Python 引擎计算的合成数据，验证图表、指标、保存恢复、参数变更提示、失败、嵌套关闭、基金切换和移动布局。模拟保存仅位于测试页面，不写生产数据库。

单次历史回测不等于规则已经有效，也不代表通过多基金、不同市场阶段和样本外检验；不做自动调参或收益承诺。

## v2 平衡候选与对照（2026-09-30）

- 该阶段（现已被 v3.1 替代）的今日推荐默认 NAV-TA v1；回测可选择 `NAV-TA v2-balanced`。两个版本由同一 Python 模块实现，不覆盖既有首页量化策略。
- v2 买入：净值 > MA20 > MA60，MA20 较 5 点前上行，DIF > DEA 且 >0，RSI14 为 45–70，净值正乖离不超过 5%。取消 MA5/MA10 排列和完整周线的强制确认。
- v2 减仓：净值 < MA20、MA20 下行、DIF < DEA；不等待跌破 MA60、MACD 零轴或周线确认。周线仍显示为辅助证据，覆盖不足不会伪造确认。
- v2 QDII 新鲜度允许最多 2 个工作日、6 个自然日；其他数据质量门槛仍保留。QDII 的 v1/v2 比较同时涉及披露门槛差异，不能简单归因为策略收益改善。
- 增加 `initialPositionPercent`（默认 0）和 `ruleVersion`（默认 v1），旧请求和历史结果兼容。期初建仓按起点净值、相同申购费执行，从起点计算持有期与确认延迟，单独标记 `INITIAL_BUY`；不冒充技术信号或真实账户历史持仓。
- 引擎版本升级 NAV-REPLAY v2。每次运行固定比较两个版本在全区间、前 70% 参考段、后 30% 留出段的收益、回撤、交易及可分析日。前段至少 60 点，后段至少 40 点，否则显示验证样本不足。
- 每段独立以相同初始资金和建仓比例重新开始，前段仅用于对照，不执行参数搜索。指标可读取段起点之前已披露的预热数据，不能读取未来数据。0 成交或不足 3 笔规则交易显示样本不足；3 笔不是统计有效的证明。
- 不按回测收益自动挑选版本。旧保存结果不会被重写，重新运行后才包含对照表。详细首轮结果见 `nav-rule-comparison-2026-09-30.md`。

测试增加候选规则无未来泄漏、QDII 数据门槛、期初资金/费用守恒、确认锁定、固定时间切分及前段不受后段数据改变影响。


## v3.1 正式接入（2026-10-01）

- 固定版本 `NAV-TA v3.1-trend`，参数 `T70-B2-F20-S18-I3`：MA70 ±2%，连续 3 点确认及 5 点斜率，目标 100% / 20%；60 点高位回撤 18% 且跌破 MA20 触发刹车；刹车后须 MA70 趋势与连续 3 点站上 MA20、MA20 上行共同确认才恢复。
- 目标偏离超过 5 个百分点才调仓；距上次实际成交至少 3 个净值观察日。买入、减仓各 50% 为单次上限，向目标补足，避免无限减半；未成交不消耗间隔。不会因 RSI 超买或单次 MACD 交叉单独减仓。
- 新打开“回测此规则”默认本版本、模拟本金 10000、期初 100%、买入 50%、减仓 50%。历史结果需主动选择，避免旧记录静默覆盖当前版本。提供恢复审核参数按钮；兼容旧请求的 v1 / 0% 默认值不变。
- 选择 v3.1 时比较 v1 / v2 / v3.1 共 9 行（区间足够时）；选择旧版本仍保持 6 行。保存 `ruleId`、`ruleParameters`、逐日目标和已知仓位；引擎版本 NAV-REPLAY v3.1。
- 正式净值历史逐步重建趋势状态，查询不会产生交易、消耗冷却期或写入真实策略信号。实时页面读取已披露净值；回测按指定披露延迟。日历、费用、起点和实际成交不同可导致实时与某次回测状态不同。
- **实时执行边界**：系统没有单基金专属现金、待到账金额及策略执行台账，因此实时推荐是条件式方向，`executionReady=false`；不虚构当前策略仓位、可用金额或已满足成交间隔。100% / 20% 绝非账户总资产权重。无持仓时不会显示卖出指令。回测在独立模拟账本内完整核对资金、份额、冷却期与成交。
- 7 只持仓的冻结数据核对：生产版与审核版指标、曲线、逐日信号和成交日期/金额/费用完全一致。记录：`output/nav-research-2026-10-01/integration-audit.json`。研究文件保留原审核状态作为历史记录，不导入生产路由。
- 审核不是未来收益认证；既有量化策略、真实持仓、交易、旧回测均不改写。未新增路由或数据库表。本次部署仅重建并重启三个相关服务。


## 非交易日查看分析（2026-10-02）

- 实时分析取消非交易日与净值新鲜度硬阻断，使用最近已披露的正式净值；保留真实查看日期，未来净值、重复冲突、样本不足、无效收益率与历史断档等仍阻断。
