# 累计收益

累计收益使用独立账本，不参与原有持有收益、持有收益率、当日收益、现金、总资产、仓位、收益日历或策略公式。

## 显示与结算

- 首页“总收益”改名为“总持有收益”，原字段和公式保持不变。
- 新增“总累计收益”，持仓表在持有收益右侧增加“累计收益”。基金名称省略，悬停可见全名；表格内部滚动展示全部记录。
- 累计收益只读取正式净值表，忽略盘中估值、未来日期和 Mock 净值。晚间取得新正式净值后，页面请求立即刷新账本；后台每分钟也检查已保存的正式净值。
- 净值所属日期用于避免重复/回退，不要求等到日历日期相同。例如 9 月 26 日公布的 9 月 24 日净值可立即入账。
- 已确认交易独立入账：卖出记录净回款与售出部分账面价值之差；买入记录新增账面价值和手续费。剩余份额继续按正式净值计算变化。待确认交易不计入，确认后的净值日期用于防止用旧净值重估新增份额。
- 使用 8 位账本精度，展示保留 2 位；正式净值修正只更新差额。交易 ID 唯一键、同一用户的事务锁和事务回滚保证重复处理不重复记账。

## 清仓、删除、重新买入

账户+基金代码是生命周期归集键，持仓 ID 是每段持有期间的估值账本。清仓不清除累计收益。

“历史收益结转”由期初历史收益与当前没有展示持仓的基金收益相加计算。删除持仓不删除收益账本；重新添加同账户同基金时，历史金额自动归回该基金名下。这个归属变化不会更新总金额，因而不存在先加后减的中间状态或重复转移。

总累计收益 = 期初历史收益 + 所有基金账本余额。

原有直接删除非空持仓的行为保留：没有待确认交易时冻结该持仓的收益记录；有待确认交易时保留账本关联，结算仅允许按交易所属用户读取被软删除的原持仓。普通查询仍排除删除记录。

手动修改持仓份额/成本属于基准校正，不直接修改累计收益。校正后未来净值变化按新份额计算。新增的手动导入持仓从导入时建立基准，累计收益从 0 开始；升级前未指定期初金额的既有持仓用正式净值对应的持有收益建立基准。

## API

`GET /api/dashboard/cumulative-profit`（登录、用户隔离、每分钟 120 次限制）。没有累计收益写入接口，也没有编辑表单字段。

```json
{
  "totalCumulativeProfit": -765.51,
  "historicalProfit": -232.13,
  "funds": [
    {
      "accountId": 6,
      "fundCode": "012922",
      "cumulativeProfit": -109.09,
      "officialNavDate": "2026-09-23",
      "archived": false
    }
  ]
}
```

以上省略其余基金，仅示意返回结构。前端累计收益请求失败时显示未更新状态并保留上次结果，不用 0 替代、不阻断原首页数据。

## 一次性初始化

`docs/sql/012_cumulative_profit.sql` 只新增四张表，不修改原有财务表。先完成初始化，再运行新版本。

`tools/CumulativeProfitMigration.java` 从本地 `.env` 读取数据库连接，默认只检查基金代码和正式净值。通过现有 MySQL JDBC 驱动运行；加 `--apply` 才执行迁移和个性化初值。工具要求唯一账户恰好匹配七个代码，避免将个人初值套用到其他用户。

| 基金代码 | 累计收益 |
| --- | ---: |
| 017811 | -15.10 |
| 016874 | 40.65 |
| 025833 | -46.83 |
| 013403 | -93.59 |
| 012922 | -109.09 |
| 021180 | -174.10 |
| 021528 | -135.32 |

七只基金合计 -533.38，期初历史收益 -232.13，总计 -765.51。各基金用初始化时已保存的最新正式净值作为账面价值基准；这些初值已包含此前盈亏，不能再加一次现有持有收益。

初始化在事务中完成，记录版本 `user-confirmed-cumulative-2026-09-26`；重复执行不覆盖余额。已存在账本流水但没有对应初始化版本时拒绝覆盖。迁移前后比较持仓、账户、交易和收益快照的 SHA-256，验证原始财务数据未变；校验结果保存在忽略跟踪的 `quant-fund-web/qa-artifacts/cumulative-seed-verification.txt`。

回退应用可使用升级前的 Docker 镜像，保留新增账本表，不执行删除表操作。回退期间不要登记新交易；恢复新版本前须核对期间数据，避免缺少账本流水。

## 验证

`CumulativeProfitServiceTest` 使用独立 H2 数据库测试期初总额、部分/全部卖出、手续费、删除/重新买入、延迟净值、重复交易、同日修正、小数精度、手动校正、用户隔离、待确认删除和事务回滚。

前端 `dashboard.test.ts` 验证新增接口不可用时原首页计算与显示数据不受影响。
